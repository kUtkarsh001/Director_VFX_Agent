# Approach & Architecture Documentation

This document outlines the tools, frameworks, and architectural decisions made while building the EskillVeda VFX Director Agent.

## Core Frameworks & Languages

*   **Python 3.12**: Chosen for its robust ecosystem in AI/ML, native asynchronous capabilities (`asyncio`), and advanced type hinting which improves code maintainability.
*   **FastAPI**: Used as the primary web framework.
    *   *Why*: FastAPI provides exceptional performance, native `async`/`await` support (crucial for non-blocking external API calls to Replicate and Anthropic), and automatic OpenAPI documentation.

## AI Orchestration

*   **LangGraph**: Used to manage the control flow of the VFX pipeline.
    *   *Why*: Traditional linear pipelines break down when complex error recovery or conditional logic is needed. LangGraph models the pipeline as a state machine (`StateGraph`), allowing us to cleanly separate node logic from routing logic, implement loops (like our `error_recovery` node), and maintain a single source of truth via the `VFXJobState`.

## AI Models & APIs

*   **Claude 3.5 Sonnet (Anthropic API)**: Powers the `nlp_planner` node.
    *   *Why*: Claude offers state-of-the-art vision and reasoning capabilities. It acts as the "Director," parsing the user's ambiguous intent, analyzing the input image, and outputting a structured JSON execution plan.
*   **Replicate API**: Used as the serverless GPU provider for computer vision and generative models.
    *   *Why*: Avoids the complexity and cost of provisioning and maintaining dedicated GPUs. It allows us to easily chain different state-of-the-art open-source models via API calls.
    *   **Grounded-SAM (Grounding DINO + SAM)**: Used for text-prompted object segmentation. Unlike raw SAM-2 which only accepts spatial coordinates (point/box prompts), Grounded-SAM accepts free-text object labels. It internally uses Grounding DINO for zero-shot object detection, then pipes the bounding boxes into SAM for precise alpha mask generation. This is critical because our pipeline is entirely text-driven — the NLP planner outputs object names, not coordinates.
    *   **MiDaS**: Used for monocular depth estimation.
    *   **SDXL ControlNet (Depth)**: Used for the final image compositing. It utilizes the depth map generated by MiDaS to preserve the structural integrity of the original image while applying generative changes.

## Lighting Matching

The compositing node includes a **perimeter-based lighting analysis** step that runs before image generation. It samples the border pixels (top, bottom, left, right edges) of the original image at a downscaled 64×64 resolution to estimate the scene's ambient color temperature and brightness. Based on mean RGB channel analysis, it classifies the lighting as one of five conditions:

*   **Warm golden-hour** (R > B × 1.3) — injects warm ambient descriptors
*   **Cool overcast** (B > R × 1.3) — injects cool, desaturated descriptors
*   **Bright midday** (brightness > 200) — injects high-key neutral lighting
*   **Low-key dim** (brightness < 80) — injects moody, dark atmosphere
*   **Soft diffused** (neutral) — injects balanced natural lighting

This lighting descriptor is injected directly into the SDXL positive prompt alongside the user's intent, ensuring the generated content is color-matched to the original scene. This approach costs zero API calls, runs in under 50ms, and produces visually coherent composites without manual color correction.

## Image Processing & Utilities

*   **Pillow (PIL) + NumPy**: Used for local image manipulations (e.g., the `filter` node, mask union operations, lighting analysis).
    *   *Why*: Lightweight, standard libraries for Python image processing. Doing basic operations (greyscale, contrast, resizing, perimeter sampling) locally avoids unnecessary API costs and latency.
*   **Pytest**: Used for the testing framework.
    *   *Why*: Industry standard for Python testing. We utilized it to mock external API calls, ensuring the graph routing and state management could be verified quickly and deterministically without incurring API costs. The test suite covers both node logic (20 tests) and routing decisions (17 tests).

## Infrastructure & Deployment

*   **Docker & Docker Compose**: Used for containerization.
    *   *Why*: Ensures the application is perfectly reproducible across any environment. We implemented a multi-stage Dockerfile to keep the final runtime image lean and secure (running as a non-root user). The compose file includes a scaffolded worker service (currently commented out) ready for Celery-based horizontal scaling.
*   **In-Memory Store (`job_store.py`)**: Used for tracking async job states.
    *   *Why*: Provides a lightweight solution for the initial milestone that can easily be swapped for Redis in a production environment without changing the core business logic.

## Key Architectural Decisions

1.  **Fail-Fast Cost Guard**: We implemented a pre-flight cost check (configurable via `MAX_COST_PER_JOB_USD` environment variable, default $0.02) before executing any external models. The budget is read from the environment at startup, eliminating hardcoded values.
2.  **Graceful Degradation**: If the depth estimation node fails, the pipeline does not crash. Instead, it flags the error and continues to the compositing node, which falls back to standard inpainting without depth conditioning.
3.  **Asynchronous Execution**: The LangGraph pipeline runs in background tasks, allowing the FastAPI server to immediately return a `202 Accepted` response with polling URLs, rather than blocking the client connection.
4.  **Loop-Safe Routing**: All conditional routing functions check only the *latest* error in the state and verify the `retry_target` flag, preventing infinite retry loops after a successful recovery. This was a critical design fix to ensure robustness in the error recovery path.
5.  **Lighting-Aware Compositing**: Perimeter pixel analysis ensures generated content matches the source image's ambient lighting conditions, addressing the VFX "lighting matching" pillar without additional API cost.
